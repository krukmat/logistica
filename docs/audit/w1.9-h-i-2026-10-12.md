## Actual evidence

- `npm test`: **22 tests passed, 0 failed**; includes journal reopen, quota refusal, event-ID collision, cloud ACK marker, corruption refusal, and test child `SIGKILL` after a successful host `fsync` ACK.
- `npm run emulate`: seven logical scenario fixtures `SIM_PASS`.
- `npm run lab:loopback`: real localhost TCP/HTTP `LAB_PASS`; neither physical WAN nor throughput verified.
- Isolated Linux namespace runner: **`PEF_NETNS_POLICY_LAB LAB_PASS` and `PEF_NETNS_RESULT LAB_PASS CLEANUP=CLEAN`**. WAN probes were performed from the isolated Edge namespace to separate WAN peers; the logical Connectivity policy determined the preferred WAN, and the driver applied `ip route` inside *Edge only*. LAN HTTP observed WAN-A → WAN-B on primary upstream unreachability while carrier was UP → stayed on backup through failback hold → WAN-A after stable return → `LOCAL_ONLY` while both WANs unreachable and local LAN ping succeeded → recovery to WAN-A. No physical NIC modified.
- **Bug found and fixed before PASS:** deleting the synthetic WAN gateway address removed/invalidated its return path to the LAN, so merely choosing a recovered WAN and updating the Edge default route was insufficient for end-to-end HTTP. Restoring that WAN namespace's `10.250.10.0/24` return route on readdressing resolved the discrepancy. This is a concrete implementation lesson for link lifecycle and rollback: **validate bidirectional dataplane after control-plane convergence**.

The file journal is a **laboratory reference store**, not a production storage engine. ACK is issued after successful **OS fsync**, but host/device power-loss behavior remains unverified. Initial file creation does not constitute a tested durable-directory creation contract. CLOUD_ACK is an append-only marker; backlog compaction and emergency journal cursor reserve are intentionally pending W1.9.J.
