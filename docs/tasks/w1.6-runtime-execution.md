# W1.6 — Software Runtime Contract: tareas agénticas (1–2 niveles)

**Estado de ejecución de diseño:** W1.6.A–I DOCUMENTED; selección de herramientas, implementación y aceptación técnica PENDING. **Fuente:** [09 runtime contract](../09-runtime-contract.md). Contratos preexistentes: [02 requirements](../02-core-requirements.md), [03 architecture](../03-logical-architecture.md), [04 failure/offline](../04-failure-offline-contract.md), [08 resource gate](../08-resource-gate.md).

## Resumen previo al bloque

**Objetivo:** traducir cinco bloques lógicos a un runtime ejecutable sin acoplar PEF a un SoC, distribución Linux ni stack de red prematuramente. **Subtasks críticas:** A/B (procesos/boot), C/D/E (contratos y configuración), F/G/H (trust, journal, workloads). **Output:** contrato de runtime + matriz de gates W1.7. **DoD:** owners, secuencia, estados, errores y recovery definidos; no claims de pruebas o hardware.

## Subtasks y entregables

- **W1.6.A — Deployment/runtime topology** [DOCUMENTED]
  - **A1** Definir Core lógico vs separación de procesos, privilegios y dataplane.
  - **A2** Definir lifecycle/health del supervisor de procesos y aislamiento de workloads.
- **W1.6.B — Trusted bootstrap & shutdown** [DOCUMENTED]
  - **B1** Ordenar bootstrap mínimo, identidad y last-known-good sin deadlock.
  - **B2** Definir safe mode, shutdown, blackouts y validación post-reboot.
- **W1.6.C — State model & IPC** [DOCUMENTED]
  - **C1** Separar Health, Connectivity, Cloud y Security state.
  - **C2** Definir contratos de llamadas/eventos, idempotencia, timeout y errores.
- **W1.6.D — Connectivity adapters** [DOCUMENTED]
  - **D1** Definir límites WAN/LAN, network intent y configuración reversible.
  - **D2** Fijar observabilidad health activa/failover sin dependencia de cloud.
- **W1.6.E — Cloud sync protocol** [DOCUMENTED]
  - **E1** Definir handshake de revisiones/cursor; desired/effective/observed.
  - **E2** Definir idempotencia, conflictos, replay y offline entitlement limits.
- **W1.6.F — Persistence & storage recovery** [DOCUMENTED]
  - **F1** Definir durable ACK, cuarentena corrupción, cuotas P0/P1/P2/P3.
  - **F2** Definir replay, compaction, cursor atomic y boot recovery.
- **W1.6.G — Identity & signed lifecycle** [DOCUMENTED]
  - **G1** Separar device/root trust, local authorization, remote mTLS.
  - **G2** Diseñar slot candidato/last-known-good y rollback seguro.
- **W1.6.H — Workload Runtime execution** [DOCUMENTED]
  - **H1** Validación manifest, admission, resource limits, Network Intent.
  - **H2** Health/restart/backoff, no privilege escalation y offline classes.
- **W1.6.I — Design Gate** [DOCUMENTED]
  - **I1** Matriz ownership/riesgos/tradeoffs; sin selección tecnológica irreversible.
  - **I2** Conectar criterios de aceptación W1.2/W1.5 con el harness W1.7.

## Reglas de cierre

Cada task tiene input/contrato/errores/DoD en [09](../09-runtime-contract.md); el segundo nivel es opcional y nunca hay tercer nivel. **DOCUMENTED** significa contrato versionado y revisable; **IMPLEMENTED** requiere software, y **VALIDATED** requiere ensayos reproducibles. W1.6 está cerrada como *design deliverable*, **NO** como runtime funcional.

**Bloque siguiente:** W1.7 Harness Specification, que convierte tests de contrato en escenarios y artefactos reproducibles.
