# W1.9 — Virtual Edge Emulator · tasks y subtasks (1–2 niveles)

**Alcance:** emulador software-first sin hardware, independiente de plataforma; no implementa Core operativo ni sustituye ensayos físicos. [Definición técnica](../12-emulator.md).

## W1.9.A — Deterministic Edge Core · IMPLEMENTED (logical)
- **A1 — State/Connectivity:** reloj lógico, WAN link+upstream, prioridad, health `LOCAL_ONLY`, cloud/trust.
  - **A1.a:** escenarios failover, carrier-up blackhole y failback.
- **A2 — Journal/Recovery:** P1 array + ACK lógico, prepare/unacked, reboot/powercut simulado, config revision rollback.
  - **A2.a:** escenarios full-P1, ambiguous Cloud ACK y dedup.

## W1.9.B — Workload behaviors · IMPLEMENTED (logical)
- **B1 — Admission:** manifest subset, CPU/RAM/P2 requests, Network Intent allowlist.
- **B2 — Isolation:** P2 quota, crash counter, workload `ISOLATED`, remote trust isolation.
  - **B2.a:** rejection/oracle negative cases.

## W1.9.C — Agent-oriented scenario harness · IMPLEMENTED (code)
- **C1 — Declarative Runner:** scenario JSON, `SIM_PASS/SIM_FAIL`, trace/observations, no host action.
- **C2 — CLI + regressions:** Node built-in tests, seven fixtures, `npm run smoke`.
  - **C2.a:** isolado JS 6/6 scenarios passed; Node CLI run aún pendiente de registrar.

## W1.9.D — Hardware adapter handoff · DOCUMENTED
- **D1 — Ports/backend selection:** `openBackend(kind, config)` implementado como seam; `sim` disponible, `linux-lab`/`device` devuelven `SIM_BLOCKED`. Ports futuros: Clock, WanProbe, Journal, NetworkPolicy, WorkloadLimiter, RecoveryBoot, CloudTransport.
- **D2 — Linux/physical progression:** reusar escenarios; comparar resultados `sim`/ `linux-lab` / `device` y registrar divergencias.

## W1.9.E — Refinement before Linux-lab · PLANNED
- **E1:** rechazo por manifest_version y colisiones event_id ya implementado; **pendiente** validación JSON Schema completa, canonicalización cross-platform y retención O0/O1.
- **E2:** backend selector incorporado con fail-closed; queda por implementar interface real de puertos/namespace o VM Linux y fault injection seguro.

- **F1 — Mock transports**: iniciar dos upstreams HTTP loopback en puertos asignados dinámicamente; simular 503, timeout o desconexión y comprobar probe TCP/HTTP real.
- **F2 — Adapter boundary**: conservar el Core de tiempo lógico y sus IDs de escenarios; exponer observables `LAB_*` independientes, sin elevar `SIM_PASS` a benchmark.
