# W1.9 — Virtual Edge Emulator · tasks y subtasks (1–2 niveles)

**Alcance:** emulador software-first con Core reutilizable para runtime Linux/Node; sin hardware físico, drivers de device ni certificación de producto. No sustituye ensayos físicos. [Definición técnica](../12-emulator.md).

## W1.9.A — Deterministic Edge Core · IMPLEMENTED (logical)
- **A1 — State/Connectivity:** reloj lógico, WAN link+upstream, prioridad, health `LOCAL_ONLY`, cloud/trust.
  - **A1.a:** escenarios failover, carrier-up blackhole y failback.
- **A2 — Journal/Recovery:** P1 array + ACK lógico, prepare/unacked, reboot/powercut simulado, config revision rollback.
  - **A2.a:** escenarios full-P1, ambiguous Cloud ACK y dedup.

## W1.9.B — Workload behaviors · IMPLEMENTED (logical)
- **B1 — Admission:** manifest subset, CPU/RAM/P2 requests, Network Intent allowlist.
- **B2 — Isolation:** P2 quota, crash counter, workload `ISOLATED`, remote trust isolation.
  - **B2.a:** rejection/oracle negative cases.

## W1.9.C — Agent-oriented scenario harness · IMPLEMENTED (code)
- **C1 — Declarative Runner:** scenario JSON, `SIM_PASS/SIM_FAIL`, trace/observations, no host action.
- **C2 — CLI + regressions:** Node built-in tests, seven fixtures, `npm run smoke`.
  - **C2.a:** isolado JS 6/6 scenarios passed; Node CLI run aún pendiente de registrar.

## W1.9.D — Hardware adapter handoff · DOCUMENTED
- **D1 — Ports/backend selection:** `openBackend(kind, config)` implementado como seam; `sim` disponible, `linux-lab`/`device` devuelven `SIM_BLOCKED`. Ports futuros: Clock, WanProbe, Journal, NetworkPolicy, WorkloadLimiter, RecoveryBoot, CloudTransport.
- **D2 — Linux/physical progression:** reusar escenarios; comparar resultados `sim`/ `linux-lab` / `device` y registrar divergencias.

## W1.9.E — Refinement before Linux-lab · PLANNED
- **E1:** rechazo por manifest_version y colisiones event_id ya implementado; **pendiente** validación JSON Schema completa, canonicalización cross-platform y retención O0/O1.
- **E2:** backend selector incorporado con fail-closed; queda por implementar interface real de puertos/namespace o VM Linux y fault injection seguro.

## W1.9.F — Loopback Connectivity Lab · IMPLEMENTED / CI VERIFIED

- **F1 — Mock transports**: iniciar dos upstreams HTTP loopback en puertos asignados dinámicamente; simular 503, timeout o desconexión y comprobar probe TCP/HTTP real.
- **F2 — Adapter boundary**: conservar el Core de tiempo lógico y sus IDs de escenarios; exponer observables `LAB_*` independientes, sin elevar `SIM_PASS` a benchmark.
  - **F2.a — Safety**: bind sólo `127.0.0.1`, cierre en `finally`, sin manipular interfaces, firewall ni DNS del host.
- **F3 — Acceptance**: tests Node en CI para transiciones local→respaldo y pérdida total; registrar evidencia del comportamiento de sockets, no de ISP/NIC.

**Implementación:** `src/emulator/lab/loopback.js`, `bin/pef-loopback-lab.js`, `test/loopback-lab.test.js`. CI run 38253176876 pasó 12 tests Node, 7 escenarios SIM_PASS y loopback LAB_PASS. Pruebas físicas y Linux namespace aún pendientes; `LAB_PASS` sólo verifica sockets localhost.

**Diagramas normativos:** [13 — Conectividad PEF](../13-connectivity-topology.md). Sólo cuando loopback sea estable se considerará el driver `linux-lab` con aislamiento explícito.

## W1.9.G — Linux network namespace routing lab · IMPLEMENTED / CI VERIFIED

- **G1 — Linux topology fixture:** declarar una red de test con namespace Edge, WAN-A, WAN-B y una LAN simulada, con rutas sólo internas y recursos identificados por `lab_id`.
- **G2 — Preconditions and cleanup:** `linux-lab` debe requerir Linux VM/container de laboratorio explícitamente autorizado, `CAP_NET_ADMIN`, `iproute2`, confirmación de red no productiva y `finally` para destruir únicamente objetos con el prefijo propio.
  - **G2.a:** no ejecutar cambios de rutas/NAT/firewall del host ni reutilizar NIC físicas; `BLOCKED` cuando no se garantice aislamiento.
- **G3 — Same scenario trace:** contrastar HTTP/TCP/routing real sandbox frente a `sim` y `loopback-lab`; separar failover de conexiones nuevas, DNS/DHCP y métricas físicas aún pendientes.

**Artefactos:** `scripts/lab/netns-smoke.sh`, `scripts/lab/netns-client.py`, `test/netns-preflight.test.js`, `.github/workflows/pef-emulator.yml`. Las rutas se modifican exclusivamente en el namespace Edge; los veth nacen allí, sin interfaz creada en el host. El escenario verifica HTTP forwarding desde LAN hacia WAN-A/B, blackhole carrier-up, conmutación de ruta controlada y supervivencia LAN durante caída total. **No mide convergencia automática ni p95 de failover.**

**Validación:** [CI #38259618954](https://github.com/krukmat/logistica/actions/runs/38259618954) `LAB_PASS` con `CLEANUP=CLEAN`, sin certificar NIC físicas. Driver `device` continúa bloqueado.

## W1.9.H — Probe-driven Connectivity Policy · IMPLEMENTED / CI VERIFIED

- **H1 — Adapter de decisión:** `src/emulator/lab/netns-policy.js` inyecta `probe()` y `applyRoute()`; mantiene selección e histéresis en máquina de estados sin comandos host.
  - **H1.a — Adapter de Linux sandbox:** `scripts/lab/netns-policy-scenario.js` toma medidas HTTP reales a gateways WAN desde Edge, cambia **sólo la ruta dentro del namespace Edge** y comprueba que LAN observa WAN elegida.
- **H2 — Fault/recovery:** carrier UP con upstream unreachable, failover a respaldo, failback con histéresis, todas WAN sin conectividad y LAN local intacta.
  - **H2.a — Lección de implementación:** al recuperar IP de gateway WAN, restaurar también su ruta de retorno a LAN; de lo contrario el control plane aparece sano mientras el dataplane falla.
- **H3 — Evidence gate:** GitHub Actions [#38259618954](https://github.com/krukmat/logistica/actions/runs/38259618954): `LAB_PASS`, `CLEANUP=CLEAN`, oracle de HTTP bidireccional; sin p95 físico ni NAT completo.

## W1.9.I — Sandbox File Journal · IMPLEMENTED / CI VERIFIED

- **I1 — Durable write reference:** `src/emulator/lab/file-journal.js`: registro NDJSON append-only con SHA-256 y `fsync` OS antes del ACK; single-writer **por contrato, no enforcement de locks**.
  - **I1.a — Process crash:** child `SIGKILL` después de ACK seguido de reapertura e integridad de registro, no corte real de energía.
- **I2 — Pressure and synchronization:** cuota acotada, `EVENT_ID_CONFLICT`, marcador `CLOUD_ACK` fsync/reopen y error por tail corrupto sin auto-reparación.
- **I3 — Evidence:** [CI #38259618954](https://github.com/krukmat/logistica/actions/runs/38259618954) confirma **22 tests Node PASS, 0 FAIL**; durabilidad ante hardware power loss continúa NOT_RUN.

## W1.9.J — Protected Journal Lifecycle · IMPLEMENTED / CI VERIFIED (lab scope)

- **J1 — Protected control reserve** [IMPLEMENTED / CI VERIFIED]: `controlReserveBytes` mantiene espacio separado para marcadores `CLOUD_ACK` cuando se deniegan nuevas escrituras de eventos; no equivale a reserva independiente de evidencia O0/O1 ni garantiza infinitos ACKs.
- **J2 — Safe compaction** [IMPLEMENTED / CI VERIFIED]: retención O0/O1, tombstones SHA de O2/O3 ACKed, staging/fsync/atomic rename/directory fsync, reapertura y tests de interrupción.
  - **J2.a — Negative tests:** saturación, reinicio durante compaction, falta de espacio y colisiones de event_id.
- **J3 — Emulator-to-hardware traceability** [DOCUMENTED]: etiquetar `sim`/`linux-lab`/`file-journal`/`device` y declarar gates físicos aún no verificables.

**Evidencia:** [audit J2/J3](../audit/w1.9-j2-j3-2026-10-12.md), [CI #38264150746](https://github.com/krukmat/logistica/actions/runs/38264150746): 38 tests Node PASS, siete escenarios SIM_PASS y network namespace LAB_PASS. Estado físico: NOT_RUN.

## W1.9.L — Integrated Edge Runtime Slice · IMPLEMENTED / CI VERIFIED

- **L1 — Connectivity + Journal integration:** combinar `createConnectivityController` con `createFileJournal` para persistir las transiciones WAN y hechos de recuperación con `fsync` del SO antes de devolver ACK.
- **L2 — Failure semantics:** aunque falle P1, el forwarding local debe seguir; reportar `DEGRADED / STORAGE_FULL_OR_UNSAFE` y nunca una evidencia ACKed inexistente.
  - **L2.a:** presión de journal, reinicio/reapertura y duplicados de transición.
- **L3 — Shared simulator/hardware contract:** el mismo evento y su `correlation_id` viajan por `sim`, `linux-lab` y adaptador físico futuro; no confundir tiempos lógicos con throughput o fallos reales.

- **Q3 — Recovery & Cloud replay:** tras restaurar WAN, mismo `syncJournal` usado por el emulador confirma eventos al mock Cloud; admite ACK perdido/reintento idempotente. `retained()` conserva recepciones O1 al reiniciar, confirmar remotamente y compactar.
