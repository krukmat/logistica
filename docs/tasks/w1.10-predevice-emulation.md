## W1.10.B — Port hardening · IN PROGRESS
- **B1 — Verified route boundary · CI VERIFIED (software/lab):** readback, compensation and quarantine after partial route commits or rollback failure. Four new checks are visible in the existing matrix (17 total).
  - **B1.a — Negative evidence:** injected after-write failure, false positive readback, failed compensation and explicit reconciliation.
- **B2 — Bounded ports · CLOSED (software/lab, CI VERIFIED):** explicit probe/route/reconciliation deadlines, cooperative AbortSignal, quarantine until late route operation settles and readback verifies target; boot starts blocked.
  - **B2.a — Failure matrix:** slow probe, route timeout with late mutation, cooperative abort, permanently hung route and explicit boot reconciliation (six checks; 23 total).
- **B3 — Storage matrix · IMPLEMENTED / CI PENDING:** fault-injected host-fs write/fsync port, 11 deterministic checks with the shared LocalReceipts Core; durable ACK uncertainty, strict tail/checksum detection, quotas/control reserve, compaction failure boundaries and version metadata migration.
  - **B3.a — Physical distinction:** host fsync, fault hooks and simulated powercut are *not* device power-loss certification; preserve corrupted tails until supervised recovery.
- **B4 — Golden traces:** stable trace comparison Mac ↔ Linux CI ↔ future device, capture resource/latency but never extrapolate to watts.
